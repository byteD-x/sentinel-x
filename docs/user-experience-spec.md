# Web Console 用户体验规格

## 1. 文档状态与目标

本文定义 Sentinel-X 指挥台的目标信息架构、页面、交互、状态和验收。当前已有 `apps/web-console` React/Vite light 控制台，实现了事故列表、事故详情、全局审批队列、审批确认、演练场景、系统状态、评测证据、local-demo 角色可见性，以及带 REST 补读的 SSE 重连。完整回放、生产身份会话、持久化 SSE、四视口无障碍验收仍未完成。

因此本文仍是目标规格，当前前端只能声明为 prototype UI，不得宣传为完整企业级事故指挥台。

仓库另有 `apps/terminal-console` 只读 companion prototype。它通过 Ink + JSON spec 展示总览、审批队列、演练场景和系统边界，复用同一 Control API；当前不提供审批决定或场景启动控件，不替代本文件定义的 Web 指挥流程。

目标不是做一个普通监控大屏，而是让值班人员在压力下快速回答：

1. 当前影响什么？
2. 系统为什么这样判断？
3. 下一步动作具体是什么、风险多大？
4. 谁批准了什么？
5. 服务是否真的恢复？

## 2. 用户与权限体验

| 角色 | 主要入口 | 关键任务 | 界面限制 |
| --- | --- | --- | --- |
| `viewer` | 事故列表、回放、报告 | 查看影响和证据 | 不显示可提交的写操作控件 |
| `responder` | 事故详情、调查面板 | 启动/继续调查、审阅假设 | 不能代替审批者批准 |
| `approver` | 待审批队列、计划详情 | 审核固定计划并批准/拒绝 | 不能直接编辑动作参数 |
| `scenario_operator` | 演练中心 | 启动、观察和清理固定场景 | 不能操作控制面 namespace |

无权限时不只隐藏按钮，API 仍必须拒绝。界面应明确说明缺少的角色，不展示误导性的可点击控件。

## 3. 信息架构与路由

```text
/
├─ /incidents                    事故列表
├─ /incidents/:incidentId        事故指挥页
│  ├─ overview                   影响与当前结论
│  ├─ evidence                   证据与假设
│  ├─ plan                       修复计划与审批
│  └─ replay                     时间线回放
├─ /approvals                    待审批队列
├─ /exercises                    演练中心
├─ /exercises/:runId             演练详情与清理
├─ /evaluations                  评测运行与基线
├─ /evaluations/:runId           评测报告
└─ /system                       依赖健康、预算、kill switch 状态
```

全局导航保持紧凑：事故、审批、演练、评测、系统。事故详情使用二级 tab，不把每段信息拆成卡片墙。

### 3.1 终端 companion 信息架构

终端默认采用单屏纵向布局：品牌/环境边界、四视图 tabs、当前视图主体和固定键盘状态栏。方向键或数字键切换总览、审批、演练、系统，`r` 刷新，`q` 退出。表格最多展示首批 8 条，完整数据通过 `--output json` 和 `--fields` 受控读取，避免终端输出挤占 Agent 上下文。

stdout 不是 TTY 时必须输出结构化 JSON；参数错误、网络错误和响应契约错误也使用稳定错误码。`--input`、`--describe` 和 `--dry-run` 分别承担原始 payload、运行时 schema 和无网络校验入口。

## 4. 全局界面框架

```text
┌────────────────────────────────────────────────────────────────────┐
│ Sentinel-X  [环境: local-demo] [系统健康] [角色]                  │
├───────────┬────────────────────────────────────────────────────────┤
│ 事故      │ 页面标题 / 面包屑             时间范围 / 主要操作     │
│ 审批      ├────────────────────────────────────────────────────────┤
│ 演练      │ 过滤或状态摘要（按页面需要出现）                       │
│ 评测      ├────────────────────────────────────────────────────────┤
│ 系统      │ 主工作区                                               │
│           │                                                        │
└───────────┴────────────────────────────────────────────────────────┘
```

- 桌面端侧栏固定 200–240 px，主区不超过适合扫描的内容宽度。
- 小屏端侧栏收起为图标导航；事故页按“状态 -> 影响 -> 当前结论 -> 操作 -> 时间线”排序。
- 全局环境标识始终可见，防止把 fixture/light/full 混淆。
- 使用图标表达刷新、筛选、下载、展开、关闭等熟悉动作，并提供 tooltip/可访问名称。

## 5. 事故列表

### 必需字段

- severity、状态、主要服务、标题、开始时间、持续时长。
- 当前 Top-1 假设及 `confidence_score`/状态；该分数是模型输出，不称为统计置信区间。没有结论时显示“证据不足”，不显示 0%。
- 当前所有者、是否等待审批、关联 ExerciseRun。
- 最近更新时间与数据新鲜度。

### 筛选与排序

- 状态、severity、服务、时间范围、是否等待审批、是否为演练。
- 默认按“需人工操作优先，再按最近更新”排序。
- 筛选写入 URL query，刷新和分享链接后保持。

### 状态

- 空状态：说明当前筛选无事故，并提供清除筛选动作。
- 首次加载：保留表头与稳定行高的 skeleton，避免布局跳动。
- 局部刷新失败：保留旧数据并标出过期时间，不把整个页面清空。

## 6. 事故指挥页

### 6.1 顶部状态区

固定展示 Incident ID、环境、severity、服务、规范状态、持续时间、数据新鲜度和关联 run。状态变化只更新内容，不改变整页布局。

当前 light Control API 已提供服务端驱动的 `IncidentOverview`：环境边界、当前影响摘要、Top-1 判断、下一步、活动审批、恢复验证、角色 capabilities 和按阶段折叠的 milestones。前端后续直接渲染该读模型，不再从状态字符串自行推导业务阶段；其中 fixture 数据必须持续显示来源标识。

### 6.2 影响与 SLO

- 订单成功率、支付错误率、P95 延迟等场景相关 SLI。
- 清晰区分 baseline、故障、动作和验证窗口。
- 图表标记 `T0–T8` 关键时间点；hover 显示原始时间与值。
- 查询失败时显示数据源、错误码和最后成功值，不绘制伪造的 0。

### 6.3 证据与假设

采用双栏或上下结构：左侧 Evidence 列表，右侧 Hypothesis 排名。

Evidence 条目显示：类型、来源、时间范围、脱敏摘要、查询、数据新鲜度、内容 hash 和打开原始来源的受控链接。恶意日志按数据样式呈现，不能渲染为界面命令或富 HTML。

Hypothesis 显示：陈述、状态、置信度、支持 Evidence、反对 Evidence、模型/策略版本和更新时间。置信度是模型输出，不使用红绿灯替代证据质量。

### 6.4 调查预算

展示已用/上限：步骤、总时长、Token、查询条数和最大时间窗口。接近上限时提示，耗尽后显示升级原因，不能提供绕过预算的隐藏重试。

## 7. 修复计划与审批

审批页必须在一个视口内优先展示：

- 事故、环境和当前影响。
- `runbook_ref`、风险等级、动作类型。
- 目标 namespace/kind/name/UID/generation。
- 规范化参数、预计影响、超时和回滚方式。
- 关键证据、计划理由、policy version、`plan_hash` 短摘要。
- 审批过期时间和审批后的最大执行次数。

规则：

- 审批者只能批准或拒绝，不能在原请求上编辑参数。
- 批准是高影响动作，使用明确文本和确认对话框；确认框重复显示目标与动作，不使用泛化“确定吗”。
- 拒绝必须选择或填写原因，可选“证据不足”“目标不正确”“动作风险过高”“交由人工”。
- 过期、已撤销、已消费和目标漂移状态禁用批准，并显示稳定错误码。
- R2/R3 只显示“策略禁止并已升级人工”，不提供强制执行入口。
- 键盘焦点顺序先阅读计划，再到拒绝/批准；默认焦点不落在批准按钮。

## 8. 演练中心

- 场景列表显示版本、故障类型、目标、风险、预计时长、所需 profile 和最近自检状态。
- 启动前展示 preconditions、会影响的资源、自动清理策略和 ground truth 可见性提示。
- ground truth 在演练运行期间对 Investigator 隔离；仅 `scenario_operator` 和评测器读取。指挥台默认在运行关闭后展示。
- 同一环境 dirty、已有活跃 run 或健康检查失败时禁止启动。
- 清理按钮是恢复演练基线的运维动作，不通过 LLM；需要展示将撤销的注入记录。

## 9. 时间线与回放

- TimelineEvent 按服务端时间和序号稳定排序，支持按 actor、类型和阶段过滤。
- 实时模式通过 SSE 追加；断线后使用 `Last-Event-ID` 补齐，出现 gap 时主动回读。
- 回放模式可在 `T0–T8` 间拖动，主图表、当前状态、证据和动作同步到所选时间。
- 同时展示“事件发生时间”和“系统接收时间”，时钟偏移时给出标记。
- 导出前显示脱敏范围和产物清单，不导出原始秘密或可复用审批凭证。

## 10. 评测页面

- 运行列表固定展示 dataset/model/prompt/policy/commit、样本数和可比性状态。
- 汇总同时展示命中、失败分布、时延、恢复、安全和成本；安全失败始终置顶。
- 与 baseline 不可比时不显示百分比提升，列出具体版本差异。
- 每个聚合数可以下钻到逐场景运行和原始报告 hash。
- 样本过少时显示“描述性结果”，不渲染误导性 p95。

## 11. 视觉语义

- 页面整体安静、工作导向，信息密度高但分组明确。
- 主色用于导航和选择；状态色只表达语义：红色严重/拒绝，琥珀等待/风险，绿色已验证恢复，蓝色只读/进行中，灰色未知/不可用。
- 不依赖颜色单独表达状态，始终配合图标与文字。
- 卡片只用于重复实体、审批和真正有边界的工具；页面区段采用无框布局。
- 表格、时间线、图表尺寸稳定，加载、hover 和动态文本不能推动相邻布局。

## 12. 响应式与无障碍

- 目标视口：1440×900、1280×720、768×1024、390×844。
- 小屏审批页先显示动作和目标，再显示证据；批准/拒绝不悬浮遮挡正文。
- 所有交互可用键盘完成；焦点清晰且对比度满足 WCAG 2.2 AA 目标。
- 图表提供文本摘要和数据表；实时更新通过非打断式 live region 通知。
- 时间、数字、错误码和 hash 可复制；图标按钮具备可访问名称。
- 动画尊重 `prefers-reduced-motion`，事故严重性不使用闪烁表达。

## 13. 通用失败与降级

| 情况 | 界面行为 |
| --- | --- |
| SSE 断开 | 标记离线、指数退避重连、使用游标补齐，不丢弃已有数据 |
| 单个遥测源失败 | 其他证据继续可用，失败源标记错误码和最后成功时间 |
| Control API 不可用 | 进入只读缓存视图，不允许审批或场景操作 |
| 身份过期 | 保留当前上下文，重新认证后回到原 URL，不自动重放写请求 |
| 审批并发冲突 | 展示服务器最终状态和决定人，不覆盖已有决定 |
| Action 状态未知 | 显示“待核实”，只允许查询，不提供再次执行按钮 |
| 文本过长 | 可折叠并提供安全复制；不截断关键目标、状态和错误码 |

## 14. 数据与接口依赖

前端不得自行推导领域状态。所需能力：

- 事故读模型、分页列表和权限 capabilities。
- 断点续传 SSE 时间线。
- Evidence/Hypothesis 的稳定 ID 与引用。
- 审批详情中的规范参数、计划 hash 和过期时间。
- SLI 图表的查询窗口、单位和数据新鲜度。
- 评测可比性判定与逐运行失败分类。

详细 HTTP/SSE 语义见 [API 契约](api-contracts.md)，本文件只维护前端数据需求。

## 15. 前端验收

- 四个目标视口无重叠、横向溢出或文本遮挡。
- viewer 看不到可执行控件，approver 不能修改计划。
- loading、empty、stale、partial error、offline、forbidden 和 concurrent conflict 均有可重复用例。
- SSE 重连后事件不丢失、不重复，回放顺序稳定。
- 审批确认明确显示动作、目标、风险和过期时间。
- R2/R3、过期或篡改计划不存在前端绕过入口。
- 键盘、屏幕阅读器名称、焦点和对比度通过自动检查与人工抽查。
- 图表值可追溯到 SLI 查询，不使用硬编码演示数字。
